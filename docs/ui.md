# TrashRadar — UI/UX Specification

> Статус: Draft v1.1 (враховано уточнення: категорійна модель, «нуль браузингу»)
> Дата: 2026-07-08
> Базується на: [product.md](product.md)
> Роль документа: проєктування інтерфейсу. Без реалізації — лише поведінка, компоновка та wireframe.

## 0. Дизайн-принципи

Усі рішення в цьому документі виводяться з шести правил:

1. **Нуль браузингу.** В інтерфейсі немає дерева каталогів, списку «всіх файлів» і карти диска. Користувач бачить лише те, що детектори вже визнали кандидатом на видалення, — згруповане за категоріями. Вхідна точка будь-якого шляху — категорія, а не папка.
2. **Цифра — перша.** Головний екран відкривається відповіддю «N ГБ можна звільнити». Кожен наступний екран — деталізація цієї цифри.
3. **Кожен піксель працює.** Немає декоративних відступів, банерів, «повітря заради краси». Щільність — як у професійних інструментах (DAW, NLE, IDE), а не як у консюмерських застосунках.
4. **Рішення за превью.** Користувач має вирішити «залишити чи видалити» *не відкриваючи файл*. Тому превью — найбільший елемент інтерфейсу, а не мініатюрка.
5. **Мінімум вікон, руки на місці.** Ніяких додаткових вікон; єдиний оверлей у продукті — підтвердження REAP. Панелі — вбудовані, не модальні. Два рівноправні способи керування: повністю клавіатурний і «одна рука на миші» (режим Live Preview, розділ 10).
6. **Небезпечне — помітне, але не страшне.** Все видалення йде через Quarantine, тому UI не залякує модалками; він лише чітко маркує деструктивні дії кольором і дає миттєвий шлях назад.

### Темна тема (єдина)

Палітра описується ролями, не значеннями (точні токени — на етапі дизайн-системи):

| Роль | Опис |
|---|---|
| Фон основний | Майже чорний, глибокий нейтральний — щоб превью «світилися» на ньому, як у відеоредакторі |
| Фон панелей | На пів тону світліший за основний; межі панелей — тонкі лінії, не тіні |
| Текст основний | Світло-сірий, не чисто білий (менше втома очей) |
| Текст вторинний | Приглушений сірий — шляхи, дати, метадані |
| Акцент «розмір/увага» | Тепла шкала: чим більший файл — тим «гарячіший» індикатор (жовтий → помаранчевий → червоний) |
| Деструктивна дія | Червоний. Використовується ТІЛЬКИ для видалення, ніде більше |
| Безпечна дія / відновлення | Зелений |
| Позначення (selected for reaping) | Червона рамка + напівпрозоре червоне затемнення поверх плитки |
| Quarantine | Бурштиновий (amber) — «файл у передсмертному стані» |

Типографіка: один шрифт-гротеск для UI + моноширинний для шляхів і розмірів (шляхи вирівнюються, розміри легко порівнювати оком).

## 1. Sidebar (ліва навігаційна колонка)

**Призначення:** список категорій-детекторів з обсягами. Це не дерево каталогів і не список папок — це зміст відповіді «що можна видалити», завжди перед очима.

**Поведінка:**

- Ширина: вузька, іконка + назва + обсяг; згортається до самих іконок одним кліком або клавішею `[` — у згорнутому стані звільняє місце під сітку.
- Зверху — пункт **Cleanup** (головний екран) з живою цифрою «скільки можна звільнити».
- Далі — **категорії**, відсортовані за обсягом (найважча зверху, порядок оновлюється після скану): Старі відео, Дублікати, Архіви, Артефакти розробки, Тимчасові файли, Кеші, Інсталятори/ISO, Великі файли, Старі файли…
- Категорії наповнюються під час скану: обсяги ростуть у реальному часі, порожні категорії — приглушені.
- Біля Quarantine — постійний лічильник: кількість файлів і обсяг. Бачити його завжди = довіра до системи безпеки.
- Внизу — компактний блок дисків: рядок зі смужкою заповнення на диск (лише статус і перезапуск скану — не навігація по вмісту).
- Прогрес активного скану — кільце на пункті Cleanup; сканування не блокує навігацію.

**Wireframe (розгорнутий стан):**

```

│ ◉ TrashRadar       │
├────────────────────┤
│ ▦ Cleanup   142 ГБ │  ← головна цифра, живе оновлення (72% скану)
├────────────────────┤
│ ▶ Старі відео 58 ГБ│  ← категорії за вагою
│ ⧉ Дублікати   27 ГБ│
│ ▤ Архіви      22 ГБ│
│ ⚙ Dev-сміття  18 ГБ│
│ ♻ Тимчасові   17 ГБ│
│ ▨ Кеші         9 ГБ│
│ ⬇ Інсталятори  7 ГБ│
│ ◼ Великі файли  …  │
│ ◻ Старі файли   …  │
├────────────────────┤
│ ☣ Quarantine 214│12G│
├────────────────────┤
│ C: ▓▓▓▓▓▓▓░ 91% ⟳  │
│ D: ▓▓▓░░░░░ 44% ⟳  │
```

## 2. Верхня панель (Top Bar)

**Призначення:** контекст поточного режиму + фільтри + «кошик сесії». Панель одна, тонка, завжди видима. Другого рядка немає — усе в один рядок.

**Зони зліва направо:**

1. **Контекст:** поточна категорія та її обсяг («Старі відео · 58 ГБ · 214 файлів») + охоплення сканування (які диски) з кнопкою повторного скану.
2. **Фільтр-чипси (уточнення в межах категорії):** Розмір ▾ / Тип ▾ / Вік ▾ / Диск ▾ — випадайки з пресетами (">1 ГБ", "6+ міс без доступу"). Активний фільтр — заповнений чип із хрестиком. Комбінуються. Це звуження вже знайдених кандидатів, а не пошук по диску.
3. **Сортування:** за розміром (дефолт) / датою / шляхом.
4. **Пошук** за іменем/шляхом серед кандидатів (гаряча клавіша `/`).
5. **Кошик сесії (Reap Bar)** — праворуч, найпомітніший елемент панелі: «Позначено: N файлів · X ГБ» + кнопка **[ REAP ]** (червона). Це постійний підсумок і головна CTA екрана.

**Wireframe:**

```
┌────────────────────────────────────────────────────────────────────────────┐
│ Старі відео · 58ГБ · 214 ф. ⟳ │ [>1ГБ ✕][Вік ▾][Диск ▾] │ Сорт ▾ │ 🔍 /  │
│                                        Позначено: 37 · 46.2 ГБ  [ REAP ]  │
└────────────────────────────────────────────────────────────────────────────┘
```

## 3. Головний екран: Cleanup Summary

**Призначення:** за 3 секунди відповісти на два питання: **«скільки я можу звільнити»** і **«з чого почати»**. Це не звітність і не огляд диска — це меню готових рішень.

**Блоки:**

- **Головна цифра:** «142 ГБ можна звільнити» — найбільший текст у всьому продукті. Під час скану цифра росте на очах (живий лічильник — це і є індикатор прогресу).
- **Ряди категорій:** кожна категорія — широкий клікабельний ряд: назва, обсяг, кількість файлів, смужка-частка від загальної цифри і 4–6 мініпревью найбільших кандидатів прямо в ряду. Клік по ряду = відкрити категорію; клік по мініпревью = відкрити категорію одразу на цьому файлі.
- **Швидка дія на «безпечних» категоріях:** тимчасові файли, кеші, dev-артефакти неактивних проєктів мають кнопку [Позначити все] прямо в ряду — без заходу всередину.
- **Пульс Quarantine:** тонкий рядок унизу — скільки чекає, коли автоочищення, кнопка «Звільнити зараз».

Пустого стану «привітання» немає: перший запуск одразу стартує скан і показує зростаючу цифру. Дисків як навігації на цьому екрані немає — лише охоплення скану у верхній панелі.

**Wireframe:**

```
┌ Sidebar ┬──────────────────────────────────────────────────────────────────┐
│         │                                                                  │
│         │        142 ГБ МОЖНА ЗВІЛЬНИТИ          (скан C: D: · 72% ⟳)      │
│         │                                                                  │
│         │──────────────────────────────────────────────────────────────────│
│         │ ▶ СТАРІ ВІДЕО      58 ГБ · 214 ф. ▓▓▓▓▓▓░░ ┌──┐┌──┐┌──┐┌──┐  →   │
│         │                                            └──┘└──┘└──┘└──┘      │
│         │ ⧉ ДУБЛІКАТИ        27 ГБ · 96 груп ▓▓▓░░░░ ┌──┐┌──┐┌──┐┌──┐  →   │

│         │ ▤ АРХІВИ           22 ГБ · 310 ф.  ▓▓░░░░░ ┌──┐┌──┐┌──┐┌──┐  →   │
```

## 4. Категорії файлів (категорії-детектори)

**Призначення:** категорія — головна одиниця навігації продукту. Це не фільтр по типах файлів, а результат роботи детектора: «ось група кандидатів на видалення і чому вони тут».

**Набір категорій MVP:** Великі файли · Старі файли · Забуті відео · Дублікати · Архіви · Інсталятори та ISO · Тимчасові файли · Кеші програм · Артефакти розробки (node_modules, build/dist, Unity Library…).

**Поведінка:**

- Вхід у категорію — з Sidebar або з ряду на Cleanup Summary. Всередині — сітка кандидатів (розділ 5) у тому самому вікні; жодних нових вікон.
- Над сіткою — тонкий рядок пояснення детектора: *«Відео понад 500 МБ, останній доступ понад 6 міс тому»* — користувач завжди розуміє, чому файли тут. Пороги детектора можна підкрутити прямо в цьому рядку (випадайки), без походу в Налаштування.
- Перемикання між категоріями — клавішами `Ctrl+↑/↓` або кліком у Sidebar; позначення зберігаються між категоріями (один спільний Reap Bar на всю сесію).
- Файл, що входить у кілька категорій, має маркер «також у: Дублікати» — рішення, прийняте в одній категорії, застосовується всюди.
- **Особливе подання для Дублікатів:** сітка групами — ряд групи містить усі копії файла поруч (однакові превью), обраний до збереження екземпляр підсвічений зеленим (розумний дефолт), решта — попередньо позначені. Один клік «прийняти» на групу або масово на всі групи.

**Wireframe (шапка категорії + приклад групи дублікатів):**

```
┌──────────────────────────────────────────────────────────────────────┐
│ ⧉ ДУБЛІКАТИ · 27 ГБ · 96 груп                                        │
│ Детектор: побайтово ідентичні файли · мін. розмір [50 МБ ▾]          │
│ Дефолт: залишати [найстаріший шлях ▾]     [Прийняти всі дефолти]     │
├──────────────────────────────────────────────────────────────────────┤
│ ГРУПА · wedding_final.mp4 · 3 копії · 4.2 ГБ кожна                   │
│ ┌────────┐ ┌────────┐ ┌────────┐                                     │
│ │PREVIEW✓│ │PREVIEW╳│ │PREVIEW╳│   ✓ = залишити (зелена рамка)       │
│ │D:\work │ │C:\dl   │ │D:\bkp  │   ╳ = позначено до видалення        │
│ └────────┘ └────────┘ └────────┘                       [Прийняти ✓]  │
└──────────────────────────────────────────────────────────────────────┘
```

## 5. Сітка кандидатів (Radar Grid) — головний робочий екран

**Призначення:** серце продукту. Тут ухвалюється 90% рішень «залишити чи видалити». Сітка завжди показує **вміст однієї категорії-детектора** — у продукті немає режиму «всі файли диска».

**Компоновка плитки:**

- Превью займає ~85% площі плитки. Смуга метаданих — один компактний рядок унизу поверх превью (напівпрозора підкладка): розмір (моноширинний, великий) · вік · хвіст шляху.
- Розмір файла — найпомітніший текст на плитці. Індикатор «гарячості» — тонка кольорова смужка по верхньому краю плитки (жовта → червона за розміром).
- Для відео: превью = кадр + тривалість у куті; при наведенні — скраб-прев'ю (протягування курсором по плитці гортає кадри).
- Для не-візуальних файлів (архів, ISO): велика іконка типу + ім'я великим шрифтом — плитка не «порожніє».
- Плитки для папок-груп (node_modules тощо): іконка групи + к-сть елементів + сумарний розмір, позначаються як одне ціле.

**Щільність:** три ступені масштабу плиток (клавіші `-` / `=`): Compact / Standard / Large. Проміжків між плитками майже немає (мінімальний зазор, щоб читались межі).

**Реалізація (замок від регресій):** віртуалізована сітка живе в
`ui/src/components/VirtualCandidateGrid.tsx` + `ui/src/components/candidate-grid/`.
Інваріанти (не `width:1`, не гейт `measured &&`, `active` з CategoryScreen,
0-заміри з `display:none` ігнорувати) задокументовані в
`candidate-grid/README.md` і перевіряються `npm run test:grid`.
Не правити геометрію «на око» в JSX — лише через `geometry.ts`.

**Позначення до видалення (reap-мітка):**

- Мишею: клік по плитці = позначити/зняти (у стандартному режимі; у Live Preview — інакше, див. розділ 10).
- Клавіатурою: стрілки — навігація, `Space` — позначити, `Shift+стрілки` — діапазон, `A` — усе в поточному фільтрі.
- Позначена плитка: червона рамка + затемнення + іконка коси у куті. Лічильник у Reap Bar оновлюється миттєво.
- `K` (keep) — «залишити»: плитка отримує зелену позначку і ховається з видачі кандидатів (рішення прийняте, не показуй знову цієї сесії).

**Прогресивне сканування:** нові знахідки з'являються знизу без зсуву того, що користувач уже роздивляється; тонка стрічка «+128 нових знахідок ↓» замість перемішування сітки.

**Wireframe:**


## 6. Панель деталей (Details Panel)

**Призначення:** контекст для сумнівних випадків, коли превью недостатньо.

**Поведінка:**

- Викликається `Enter` або подвійним кліком; відкривається праворуч як колонка (не модалка — сітка залишається видимою і керованою).
- Вміст: максимально велике превью (для відео — програвання скрабом), повний шлях (клікабельний — «показати у провіднику»), розмір, дати (створено / змінено / останній доступ), для відео — тривалість і роздільність, для груп — розбивка вмісту.
- Дії внизу: [Позначити] [Залишити] [Відкрити папку]. Ті самі клавіші, що в сітці, працюють і тут — панель не «краде» фокус.

## 7. Quarantine екран

**Призначення:** «передсмертна зона» файлів. Дві задачі: впевнено відновити потрібне і впевнено добити непотрібне.

**Поведінка:**

- Та сама сітка з превью, що й у Radar (звична механіка), але в бурштиновій рамці режиму: користувач завжди розуміє, що він «усередині кошика».
- На кожній плитці — таймер до автознищення («залишилось 11 дн»); файли, що згорають найближчим часом, — угорі.
- Дії на плитці: `R` / кнопка — відновити на початкове місце (зелена, миттєва, без підтверджень); позначення + [Знищити] — остаточне видалення (єдине місце у продукті з жорстким підтвердженням).
- Верхній рядок екрана: сумарний обсяг, дата найближчого автоочищення, [Відновити позначені] [Знищити позначені] [Спорожнити все].
- Пошук і сортування: за датою видалення / датою згорання / розміром / початковим шляхом.
- Після відновлення — тост «Відновлено у D:\...» з кнопкою «Показати».

## 8. Bulk Delete екран (підтвердження REAP)

**Призначення:** останній погляд перед відправкою у Quarantine. Не «страшилка», а швидка перевірка: *чи не потрапило зайве*.

**Поведінка:**

- Відкривається кнопкою [ REAP ] або `Ctrl+Enter`. Повноекранний оверлей поверх сітки.
- Заголовок-підсумок: «37 файлів · 46.2 ГБ → Quarantine». Поруч — прогноз диска після очищення.
- Список позначеного — компактні рядки з міні-превью, згруповані за папками (легко помітити «ой, це ж уся папка проєкту»).
- Кожен рядок можна викинути зі списку одним кліком (✕) — не вертаючись у сітку.
- Підозрілі позиції система піднімає нагору з маркером «?»: файли з нещодавнім доступом (< 7 днів), файли з робочого столу/документів. Це м'яка підказка, не блокування.
- Головна кнопка: **[ Відправити у Quarantine ]** — без введення слів-підтверджень, бо дія оборотна. Поруч дрібніше: «Автознищення через 30 дн · можна відновити будь-коли».

## 10. Live Preview Mode («двомоніторний режим») ★

**Призначення:** максимальна швидкість тріажу на широкому/подвійному екрані. Ідея користувача, зведена у формулу:

> **Ліворуч воджу — праворуч бачу величезним — клік виконує заздалегідь обрану дію.**

Це «перегляд як у Windows Explorer», але доведений до інструмента: превью-панель не маленька збоку, а **на весь другий монітор**, і клік — це не «відкрити», а **дія**.

### 10.1. Вмикання і компоновка

- Вмикається кнопкою `▐▐` на верхній панелі або клавішею `P`. Стан запам'ятовується.
- Вікно розтягнуте на два монітори: **ліва зона** (≈ перший монітор) — сітка мініплиток + вся навігація; **права зона** (≈ другий монітор) — суцільне превью без рамок, полів і підписів усередині. Межу між зонами можна перетягнути й вона запам'ятовується — тож права зона точно збігається з фізичним монітором.
- Права зона не має власних контролів (нуль втрат площі): вся інформація про файл — тонкий рядок-накладка знизу превью (шлях · розмір · вік), що зникає через 2 с бездіяльності курсора.

### 10.2. Механіка «наведення = превью»

- **Просто наведення** курсора на плитку зліва — праворуч миттєво з'являється файл на весь екран. Без кліку, без затримки-«роздумів»; наступний файл при переміщенні курсора замінює попередній одразу.
- Для відео: при утриманні курсора на плитці превью праворуч починає відтворення без звуку; горизонтальний рух усередині плитки = скраб по таймлайну на великому екрані.
- Для зображень: повний розмір або вписане — перемикання коліщатком.
- Клавіатурна навігація стрілками робить те саме: фокусна плитка = велике превью. Мишею чи клавіатурою — механіка одна.

### 10.3. «Озброєна дія» (Armed Action)

Зверху лівої зони — **панель дій**. Користувач один раз обирає дію, і далі кожен клік по плитці виконує її негайно:

- Дії: **Позначити (reap)** · **Залишити (keep)** · **Перемістити у…** (з обраною цільовою папкою) · **Відкрити папку** · **Нічого (тільки перегляд)**.
- Обрана дія — «озброєна»: панель підсвічується кольором дії (червона для reap, зелена для keep…), і **курсор над плитками змінює вигляд** на іконку дії. Неможливо забути, що зараз робить клік.
- Клік по плитці = дія застосована миттєво + короткий візуальний відгук на плитці (плитка позначилась/зникла/поїхала). Жодних підтверджень — усе деструктивне все одно йде через Quarantine.
- Швидке перемикання дій: `1`–`5` або коліщатко над панеллю дій. `Esc` — розрядити (повернутись до «Нічого»).
- Права кнопка миші — завжди протилежна дія до озброєної (озброєно reap → права кнопка = keep). Тріаж двома кнопками без руху до панелі.
- Захист від випадкових серій: якщо озброєно деструктивну дію і курсор бездіяльний 60 с — дія автоматично розряджається (таймаут налаштовується, розділ 9).

### 10.4. Потік роботи (цільовий сценарій)

1. Користувач вмикає Live Preview, тягне межу так, що превью займає весь правий монітор.
2. Озброює дію «Позначити» (панель і курсор червоніють).
3. Веде курсором по плитках зліва, дивиться на правий монітор: дубль — клік (позначено) — веде далі; фінальна версія — права кнопка (keep, файл ховається з кандидатів).
4. Reap Bar накопичує підсумок; наприкінці — `Ctrl+Enter` → екран Bulk Delete (розділ 8) → Quarantine.

**Мета за швидкістю: одне рішення = один рух ока + один клік. Жодних подвійних кліків, меню чи діалогів у циклі тріажу.**

### 10.6. Деталі поведінки, важливі для швидкості

- Мініплитки зліва в цьому режимі — щільніші й дрібніші, ніж у звичайній сітці (їхня задача — бути «пультом», а не носієм превью: превью тепер праворуч).
- Плитка після дії reap лишається на місці (затемнена, перекреслена) — сітка не «стрибає», рука не втрачає позицію. Приховування опрацьованих — окремим перемикачем.
- Превью наступних 2–3 плиток за напрямом руху курсора підвантажуються наперед — праворуч ніколи не «біле».
- Live Preview працює на всіх сіткових екранах: будь-яка категорія-детектор і Quarantine (там озброєні дії — «Відновити»/«Знищити»). Перемикання категорій `Ctrl+↑/↓` не виходить з режиму — тріаж кількох категорій поспіль без пауз.
- На одному моніторі режим теж доступний: права зона займає ~55% вікна (це і є «як у Windows, тільки оптимальніше» для одного екрана).
