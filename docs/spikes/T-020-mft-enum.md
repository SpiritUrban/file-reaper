# Спайк T-020 — читання MFT тому, час до повного переліку

> Статус: ✅ Завершено · Дата: 2026-07-08
> Задача: [tasks.md](../tasks.md) T-020 (E3 / F3.1)
> DoD: «Звіт: час/пам'ять на еталонному томі; go/no-go підтверджує драйвер D1»
> Інструмент: [`spikes/mft-enum`](../../spikes/mft-enum) (самодостатній FFI-бінарник, без зовнішніх крейтів)

---

## 1. Питання спайку

Драйвер **D1** ([architecture.md](../architecture.md) §0, §15): «цифра "N ГБ можна звільнити" — за секунди, не хвилини». Ціль §15: перша цифра на NTFS-томі ~1.5 млн файлів (теплий диск) — **< 10 с**.

Спайк перевіряє: чи можна прочитати метадані *всіх* файлів тому за секунди, і який бюджет пам'яті це вимагає, — тобто go/no-go для швидкого MFT-шляху до початку розробки продакшн-парсера (T-021).

## 2. Метод

- Перелік MFT через `FSCTL_ENUM_USN_DATA` — стандартний швидкий шлях перелічення записів MFT (той самий інтерфейс, що читає метадані всіх файлів тому за один послідовний прохід). Один volume-handle, батчі по 1 МіБ.
- Заміряно: кількість записів, wall-clock час, пропускна здатність (записів/с), обсяг прочитаних даних MFT, пікова робоча пам'ять процесу.
- Відкриття `\\.\<літера>:` потребує адмін-прав — прогін виконано з elevated-консолі (UAC).
- Заміряно **холодний** (перший після завантаження) і **теплий** (повторні) прогони: §15 задає ціль саме для теплого диску.

Машина спайку: Windows 11, NTFS-томи на SSD; таргет `x86_64-pc-windows-msvc`.

## 4. Аналіз

- **Теплий диск: GO.** Стала пропускна здатність теплого прогону ~**213–225k записів/с**. Екстраполяція на еталонні §15 1.5 млн файлів: **~6.8–7.1 с < 10 с**. Реальний C: (3.19 млн, вдвічі більший за еталон) перелічується теплим за ~14–15 с.
- **Холодний диск удвічі-втричі повільніший** (~63k записів/с, 50 с на 3.19 млн). §15 не обіцяє <10 с на холодному диску, тож цілі це не порушує, але це вказує на вузьке місце.
- **Вузьке місце — не пропускна здатність диска.** 326.5 МБ MFT читаються за 50 с холодним = ~6.5 МБ/с, що на порядки нижче за смугу SSD. Отже витрати — це per-record обробка у драйвері `FSCTL_ENUM_USN_DATA` + cold page-faults, а не сирий I/O. Теплий кеш прибирає page-faults → 3.4× прискорення.
- **Пам'ять — не проблема.** Сам перелік майже безкоштовний (4.7 МБ); утримання даних вирішено компактним індексом T-015, і проєкція вкладається в бюджет.

## 5. Вердикт Go/No-Go

**GO** для стратегії «метадані MFT, а не обхід каталогів». Драйвер D1 підтверджено на теплому диску з запасом; бюджет пам'яті §15 витримується.

**Умовний NO-GO для `FSCTL_ENUM_USN_DATA` як фінального механізму** — з двох причин, які має закрити T-021:

1. **`FSCTL_ENUM_USN_DATA` не повертає розмір файла.** А розмір — основа D1 («N ГБ»). Розмір лежить у сирих записах `$MFT` (`$STANDARD_INFORMATION`/`$DATA`/`$FILE_NAME`).
2. **Холодний прохід удвічі-втричі повільніший за ціль.** Сирий послідовний вичит `$MFT` (читання кластерів файла `$MFT` і парсинг FILE-записів) очікувано швидший і на холодному диску (bulk sequential I/O на швидкості SSD замість per-record driver round-trip) — і одразу дає розмір.

## 6. Рекомендації для T-021 (промисловий парсер)

1. **Реалізувати сирий парсинг `$MFT`**, а не `FSCTL_ENUM_USN_DATA`: читати `FSCTL_GET_NTFS_VOLUME_DATA` → run-list файла `$MFT` → парсити FILE-записи (заголовок + фіксапи + атрибути `$STANDARD_INFORMATION`, `$FILE_NAME`, `$DATA`). Це дає ім'я, батька, дати, атрибути **і розмір** за один прохід, з холодною швидкістю ближчою до теплої.
2. **Побудова шляхів (T-022)** — з мапи FRN → (parent FRN, name): `FSCTL_ENUM_USN_DATA` уже підтвердив, що parent-FRN доступний у кожному записі; сирий `$MFT` дає те саме через `$FILE_NAME`.
3. **Бюджет пам'яті** тримати на компактному записі T-015 — проєкція підтверджує ціль §15.
4. **Батчева видача (T-024)** великими партіями (спайк показав: 327 syscall-ів на 3.2 млн записів — синхронізація не є вузьким місцем).
5. Зберегти `FSCTL_ENUM_USN_DATA` як орієнтир/фолбек і як основу для USN-інкременталки (T-029/T-030) — там він доречний.

## 7. Відтворення

```sh
# Збірка (без зовнішніх залежностей)
cargo build --release --manifest-path spikes/mft-enum/Cargo.toml

# Запуск з elevated-консолі (потребує адмін-прав):
target\release\mft-enum.exe C     # де C — літера NTFS-тому
```

Без адмін-прав інструмент коректно повідомляє `ACCESS_DENIED (err 5)` і завершується з кодом 1.
